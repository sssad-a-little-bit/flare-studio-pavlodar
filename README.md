# Flare Studio — Batyr Studio и Picasso

Два самостоятельных демонстрационных концепта для портфолио Flare Studio. Проект работает локально и подготовлен к публикации на GitHub Pages. Формы не отправляют сообщения.

| Страница | Локальный адрес |
| --- | --- |
| Batyr Studio — автомобильные плёнки и детейлинг | http://127.0.0.1:5173/batyr |
| Picasso — детская творческая студия | http://127.0.0.1:5173/picasso |

Корневой адрес `http://127.0.0.1:5173/` также открывает Batyr Studio. Переключение между концептами доступно в подвале каждой страницы, а на Batyr — дополнительно под первым экраном.

## Запуск

Нужны **Node.js 24 или новее** и npm. Команды выполняются в каталоге `flare-studio` с файлом `package.json`.

```powershell
npm ci
npm run build
npm run preview -- --port 5173
```

После появления адреса Vite откройте нужную страницу из таблицы. Оставьте терминал работающим; остановка сервера — `Ctrl+C`. Это локальный предпросмотр готовой сборки, без развёртывания в интернете. `npm ci` устанавливает точные версии из `package-lock.json`.

Для обычной разработки с горячим обновлением:

```powershell
npm run dev
```

В текущей ограниченной Windows-среде оптимизатор зависимостей esbuild при запуске режима разработки получил `Access denied` во время поиска родительских каталогов. Поэтому для демонстрации и браузерных проверок использован успешно работающий путь **сборка → production preview** из первого блока команд. На обычной локальной машине режим `dev` остаётся стандартным режимом разработки Vite. Скрипты используют `--configLoader native`; требование Node.js 24+ учитывает этот режим загрузки TypeScript-конфига.

## Что реализовано

- Две разные визуальные композиции на русском языке, адаптивная разметка и мобильные закреплённые действия.
- Формы с проверкой обязательных полей, подготовкой редактируемого обращения, копированием и ссылкой для звонка.
- Видимый клавиатурный фокус и поддержка `prefers-reduced-motion`.
- Внешние ссылки на Instagram и карты; контакты отмечены как предварительные.

Форма ничего не отправляет и не сохраняет в браузерное или серверное хранилище. Введённые значения находятся только в памяти открытой страницы и исчезают при перезагрузке или закрытии. При копировании текст попадает в системный буфер обмена по нажатию пользователя. Ссылка `tel:` открывает обработчик звонков устройства. Интеграций записи, расчёта стоимости и WhatsApp нет.

Разрешённые реальные фотографии не предоставлены. Использованы собственные нейтральные SVG-композиции с подписью «Иллюстрация». Они не изображают реальные работы бизнеса или учеников. Блоки настоящих работ и сравнение «до/после» отсутствуют; посмотреть опубликованные материалы можно по внешней ссылке Instagram. Доступность содержимого Instagram и ссылок внутри профилей подтвердить не удалось.

## Исходники

Стек: React, TypeScript, Vite; анимация — CSS. Исходный проект был пустым.

| Файл или каталог | Назначение |
| --- | --- |
| `src/main.tsx` | Выбор страницы по URL, подключение стилей и шрифтов, метаданные |
| `src/config/index.ts` | Единая точка доступа к контенту: общие подписи и данные Batyr; экспорт Picasso |
| `src/config/picasso.ts` | Контакты, тексты и схема формы Picasso |
| `src/config/types.ts` | Общие типы конфигурации |
| `src/pages/Batyr.tsx`, `src/pages/Picasso.tsx` | Разметка отдельных концептов |
| `src/components/InquiryForm.tsx` | Общая форма и редактируемое обращение |
| `src/styles/` | Общие стили и индивидуальное оформление каждой страницы |
| `public/art/` | Нейтральные авторские иллюстрации SVG |
| `package-lock.json` | Зафиксированные версии зависимостей |

Шрифты Manrope и Golos Text поставляются локально через пакеты Fontsource; загрузка с внешнего сервиса шрифтов не требуется. Лицензии установленных пакетов находятся в `node_modules/@fontsource-variable/manrope/LICENSE` и `node_modules/@fontsource-variable/golos-text/LICENSE` после `npm ci`.

## Замена иллюстраций реальными материалами

1. Получите у владельца фотографии собственных работ, согласованные подписи и разрешения на размещение. Для Picasso отдельно подтвердите права на детские работы и согласие на публикацию портретов детей, если они понадобятся.
2. Положите оптимизированные изображения в `public/`, обновите пути, описания `alt` и подписи в конфигурации. Подпись «Иллюстрация» убирайте только у согласованных реальных фотографий.
3. Галерею настоящих работ добавляйте после получения материалов. У Batyr массив `works.gallery` оставлен пустым; для Picasso настоящий блок галереи не включён. Если добавляется модальное окно, нужны управление клавиатурой, закрытие по Esc и возврат фокуса. «До/после» допустимо только для настоящей пары фотографий одного автомобиля.
4. Сверьте контакты и все новые факты с владельцем; не переносите автоматически цены, расписание, гарантии или перечни программ из справочников. После изменений повторите сборку и проверки мобильного экрана.

Источники, ограничения исследования и полный список данных для согласования — в [RESEARCH.md](./RESEARCH.md). Выполненные проверки и их результаты — в [QA.md](./QA.md).

## GitHub Pages

Автоматическая сборка и публикация настроены в .github/workflows/pages.yml. В Settings → Pages нужно выбрать Source: GitHub Actions. После успешного workflow страницы доступны по путям /flare-studio-pavlodar/batyr/ и /flare-studio-pavlodar/picasso/ на домене аккаунта GitHub Pages.

VITE_BASE_PATH задаёт путь репозитория. Сборка создаёт отдельные index.html для обоих маршрутов, поэтому прямые ссылки и обновление страниц не требуют SPA-перенаправления.
